# Contributing

Thank you for helping. You do not need to be an expert in development or
in code: most early tasks are research, data hunting and writing.

By taking part you agree to follow our
[Code of Conduct](how-we-work/code-of-conduct.md).

## 1. Pick a task

- Start with [good first issues](https://github.com/harrythentrepreneur/open-problems/issues?q=is%3Aissue+is%3Aopen+label%3A%22good+first+issue%22)
  or browse a goal in [`goals/`](goals/) and open a target's `problem.md`.
- Each target lists its tasks under **Tasks**. Labels tell you the goal
  (`goal 06: clean water`), the kind of work (`type: research`, `type: code`,
  ...) and the size (`easy`, `medium`, `hard`).
- Only pick issues labelled `status: ready` or `help wanted`, or ask first.

## 2. Claim it

Comment **`/assign`** on the issue. A bot assigns you straight away and
sets `status: in progress`. Changed your mind? Comment **`/unassign`**.
(You can also just write "I'd like to take this" and a maintainer will
assign you.)

- One or two open tasks per person at a time, please.
- If you go quiet for **14 days** we may free the task for someone else.
  Just say if you need more time.
- Stuck? Say so on the issue, or ask in
  [Discussions](https://github.com/harrythentrepreneur/open-problems/discussions).

## 3. Do the work on a branch

```bash
git clone https://github.com/<you>/open-problems.git   # your fork
cd open-problems
git checkout -b 6.3/research-existing-tools             # see naming below
```

**Branch names:** `<target>/<short-description>`, for example
`6.3/find-open-datasets` or `docs/fix-readme-typo` for repo-wide changes.

Where things go:

| You are adding... | Put it in |
|---|---|
| Notes, sources, interview summaries | `goals/<goal>/<target>/research/` |
| Changes to the problem description | the human sections of `problem.md` |
| Code, notebooks, sample data | `goals/<goal>/<target>/solution/` (start from [`templates/solution-template/`](templates/solution-template/)) |
| Something reused across goals | [`shared/`](shared/) |

Do **not** edit the parts of `problem.md` between `<!-- UN:START ... -->`
and `<!-- UN:END ... -->`, or the tables between `INDEX` markers. They are
generated by the scripts in [`tools/`](tools/) and will be overwritten.

## 4. Check your work

You need Python 3.9 or newer. No packages to install.

```bash
python tools/check_problems.py     # validates every problem.md
python tools/build_index.py        # refreshes the README tables if you changed a status
```

## 5. Sign off and open a pull request

We use the [Developer Certificate of Origin](https://developercertificate.org/)
(DCO). It is a one-line statement that you wrote the change or have the
right to submit it. Add it with `-s`:

```bash
git commit -s -m "6.3: summarise existing satellite water quality tools"
git push origin 6.3/research-existing-tools
```

Then open a pull request. The template asks for:

- **What and why**, and the issue it closes (`Closes #12`).
- **How you checked it** (sources read, tests run, scripts run).
- **AI disclosure** (see below).

PR rules:

- Keep it small: one task per pull request.
- Cite sources for every fact: link and page number or access date.
- No personal data. Read [privacy and safety](how-we-work/privacy-and-safety.md).
- At least one maintainer review before merge. Automated checks must pass.

## AI use

You may use AI tools. You must:

1. **Say so** in the pull request (which tool, and for what).
2. **Understand and be able to explain every line** you submit, including
   code, numbers and citations.
3. **Check every fact and link yourself.** AI tools invent sources.

Full policy: [how-we-work/ai-use-policy.md](how-we-work/ai-use-policy.md).
